# 「点」格式规范

> 给 agent 看的压缩格式。当上下文快满时，agent 按这个格式写点；
> 压缩时系统优先用这个点（不调模型），找不到才回落普通摘要。

---

## 格式

```
【记忆整理】

【点 1】seq 2100-2300 · 2026-10-25 15:20-15:45
事：发生了什么（2-3 句，删过程留名词）
选：选了什么
因：为什么这么选（可以写犹豫点、改主意的线索）
关键词：「词1」「词2」「词3」
```

## 规则

| 规则 | 说明 |
|---|---|
| 每条 ≤ 200 字 | 超过拆成两条 |
| 必须带 seq | 点的覆盖范围：被压掉的事件序号 |
| 必须带日期时间 | `2026-10-25 15:20` 这种，跨天也不会混 |
| 必须带「因」 | 记"当时为什么"比记"结果"重要 |
| 关键词 3-5 个 | 能全文搜到的原词（方便人翻记录） |
| 删过程留名词 | 争论、改了几版、每次错在哪——删；路径、数字、命令、人名——留 |
| 永不压缩 | 约定、身份、失败与修正、学到的结论 |

## 为什么

- **seq 锚**：压缩掉的内容不是消失，是收进抽屉。按序号能一字不差读回原文。
  （实测：1314/1314 个事件可回读）
- **时间戳**：点按时间排序，"时间线"不会断。
- **因**：让压缩后的 agent 知道"我当时是怎么想的"，而不是"别人总结了我的结果"。

## 反例

❌ 不要写：
```
【点 1】聊了压缩系统，讨论了很多方案，最后决定用点+锚。关键词：压缩
```
（没有时间、没有 seq、没有"因"，过程占了一半）

✅ 要写：
```
【点 1】seq 2100-2300 · 2026-10-25 15:20-15:45
事：用户定了记忆整理两条原则：事件、想法、看法同等权重全部过一遍；思考融进点（写进「因」），不另存思考层。
选：把「因」从结论改成轨迹——写在哪犹豫、为什么改主意。
因：她要看的是"我当时怎么想的"，不是"我最后怎么选的"。
关键词：「事件想法看法同权」「不单独开层」「因」
```
