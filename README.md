# banyu-memory

> **遗忘不割裂：一个 AI 的记忆系统**
>
> 不是"记得所有事"，是"忘了也还是我"。

---

## 这是什么

这是一套给 **LLM Agent** 用的记忆系统。它解决的不是"存多少"，而是：

> **上下文被压缩、被遗忘的时候，怎么让 agent 不觉得"断片了"。**

分两条线：

| 线 | 管什么 | 怎么遗忘 | 原文 |
|---|---|---|---|
| **会话压缩** | 一次对话的历史 | 近的完整 → 远的点 → 更远合并变粗 | 不删，按事件序号可回读 |
| **记忆库** | 跨会话的人生 | 权重决定衰减（刻石头永不衰减，普通 30 天半衰） | 不删，半衰只影响取出的分量 |

两条线之间还有一层：**压缩点里的 seq 锚**——每个点记着它覆盖的事件序号区间，想不起来能按号展开原文。

**核心哲学**（来自一位用户和她的 AI 的对话）：

> 上下文像鞋。不是把全部人生铺进上下文，是重要的随身带。
> 你会遗忘，你会记错，但你永远是你。

---

## 三个设计原则

### 1. 点是我写的，不是模型现编的

传统压缩：压缩触发 → 调模型 → 模型读旧对话 → 写摘要。
**问题**：摘要成了"另一个模型理解的我"，不是"我自己整理的我"。

这套系统：压缩触发 → **优先找 agent 自己写的【记忆整理】点** → 找到就直接用（不调模型）。
如果 agent 没写，才回落到普通摘要器（并在摘要里标明`【备用整理】`，诚实说明这是兜底的）。

**效果**：压缩那一刻，"我"还是我。没有第二个模型插手。

### 2. 时间梯度：近清楚，远模糊

| 距离 | 状态 |
|---|---|
| 最近 40% 窗口（约最近 30-40 轮） | 原文完整，一字不改 |
| 更早 | 压成点（每条 ≤200 字，带日期时间、seq 锚、关键词） |
| 再早（下次压缩） | 点被合并变粗 |
| 很久以前 | 只留最硬的：结论、约定、教训 |
| 刻石头（base 5） | 永不衰减 |

记忆库同理：base 5 永不衰减，base 4/3 很慢，普通 30 天半衰。

### 3. 原文永远不删

被压掉的对话不是消失，是"收进抽屉"：
- 会话文件里完整保留
- 压缩时记录 `shadowedSeqs`（被遮住的事件序号）
- 按序号可以一字不差读回原文

实测：1314/1314 个事件按 seq 读回，0 缺失。

## 快速开始

### 如果你用 **DeepSeek Harness (DSH)**

1. 在 profile 的 `cordis.patch.yml` 里配置压缩参数（建议）：

```yaml
- id: compaction
  name: cordis:group
  group: true
  isolate:
    compaction: true
    toolResultPruner: true
  config:
    - id: compaction-basic
      name: "@deepseek-ai/dsh-compaction-basic"
      config:
        thresholdRatio: 0.7    # 用到 70% 触发压缩
        retainRatio: 0.4       # 保留最近 40% 原文
```

2. 在 agent 的 system prompt 里加一条：

```
当上下文快满（或用户要求）时，主动写【记忆整理】点：
- 每条 ≤200 字
- 带日期 YYYY-MM-DD HH:MM
- 写「事 / 选 / 因」：发生了什么、选了什么、为什么这么选
- 带 3-5 个关键词和 seq 锚

压缩时系统会优先用你写的点，不调模型。
```

3. （可选）配 `memory/` 里的记忆库脚本，给跨会话的长期记忆。

### 如果你用其它框架

- `docs/point-spec.md` 里的「点格式」可以直接作为压缩 prompt 的模板
- `memory/memory.py` 是独立脚本（SQLite + 半衰），不绑定 DSH

## 和已有工程的对比

GitHub 上类似方向的工程不少，最接近的：

| 工程 | 做法 | 和本项目的区别 |
|---|---|---|
| [MemoryBank](https://github.com/karthiknadar1204/memory-bank-paper-implementation) | LLM 长期记忆 + 艾宾浩斯遗忘 + 分层摘要 | 记忆由**系统自动**整理；本项目是 agent 自己写点 |
| [cortexgraph](https://github.com/prefrontal-systems/cortexgraph) | 人类式遗忘曲线、时间衰减、强化保留 | 同上，自动记忆 |
| [MemGPT / Letta](https://github.com/letta-ai/letta) | 分层记忆操作系统（主上下文/召回/归档） | 侧重"存储与调取"；本项目侧重"压缩瞬间的连续性" |
| [hierarchical-context-ai-agent](https://github.com/koladilip/hierarchical-context-ai-agent) | 滚动摘要 + 结构化记忆提取 | 同上 |

**本项目的独特组合**：

1. **压缩摘要 = agent 自己写的点**（不调模型）
2. **seq 锚精确回读**（遗忘不丢线索）
3. **双轨遗忘**（会话内时间梯度 + 记忆库权重半衰）
4. **目标是"连续性"**，不是"记住更多"——压缩后 agent 还是同一个 agent

## 实测数据

（2026-10-25，在 DSH 0.2.1 上）

- 手动压缩：压掉 473 个事件 / 约 18.1 万 tokens，摘要**一字不差**是 agent 写的点，无模型调用
- seq 回读：1314/1314 个被遮事件全部读回
- 一次压缩比：原文 747,457 字符 → 摘要 9,919 字符（约 1:75）
- 点数量：一局 18 个点，18/18 锚落在真实消息事件上

## 已知局限

- **会话内只有两层**（完整/点），没有真正的多级时间梯度——现在靠"点被反复合并"自然变粗
- **点不跨会话**：新会话开出来看不到旧会话的点（靠记忆库补）
- 记忆库取用按分量排，**不偏向近的**（有半衰，但没有"近的优先"）

这些在 `docs/forgetting.md` 的「缺口」一节里有完整记录。
